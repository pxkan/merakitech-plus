# Code review 2026-11 (v6.19 → v6.20)

> Development notes. No device was contacted for this review or its fixes: every finding was reproduced
> against the preview/SIM builds, `sim/mcu_sim.py` or `tests/mock_device.py` on 127.0.0.1.

## 1. Scope and method

**Scope:** the whole repository at commit `c9a8524` (v6.19): the UI (`src/merakiplus.c`, 9.7 k lines at the
time), the sound helper, the boot helpers (`boot/switcher.c`, `boot/grab_shim.c`, …), the installer/revert tool
(`tools/merakiplus.py`, `install.sh`, `revert.sh`), the simulator and E2E runner (`sim/`), the tests and the CI
workflows.

**Method:** four reviewers worked in parallel, each on one area:

| Area | Covers |
|---|---|
| protocol | TX safety (frame policy, write queue, STOP, recipes, power, pre-arm/cmd8, boot push, re-push), RX parser robustness |
| persist | config.json persistence, NET guard, boot slot + runtime switch, time/scheduling, sound, boot helpers |
| installer | install/revert/tooling, the mock display, hygiene/check_bins, CI workflows |
| mem-ui-sim | memory safety of graphics/UI/SIM HAL, the simulator and E2E runner as a test oracle, maintainability |

Every finding was **reproduced** before it was reported: C harnesses that `#include` the unity build
(`-DMERAKIPLUS_PREVIEW -Dmain=mp_main`), a parser fuzzer (180 000 frames, UBSan), a renderer fuzzer
(9 000 iterations, ASan+UBSan), a ctrl-socket fuzzer against an ASan SIM build, the full E2E suite under
ASan+UBSan (45/45), and failure injection on a copy of the mock display (including a pty + `dash -i` variant).
Findings the reviewers could not prove are marked UNVERIFIED and were not "fixed" blind.

**Fix rules** (CONTRIBUTING.md rule 4, docs/protocol.md, docs/dev/PARITY.md): one commit per fix, each with a
regression test in the existing test homes (preview `--selftest` in `src/mp/selftest.c`, sim scenarios via
`sim/gen_scenarios.py`, `sim/selftest.py`, `tests/test_installer.py` + `tests/mock_device.py` failure injection,
`boot/switcher.c -DSWITCHER_SELFTEST`). A UART-visible change was only allowed for a verified bug, only with frames
the stock UI also sends, and only with a test that proves the new behaviour. Line references below are in the
current `src/mp/*.c` layout (the module split from `split-modules`, see CONTRIBUTING.md "Source layout").

## 3. Checked and fine (summary of the four reports)

- **TX safety core:** no path puts a cmd6 frame on the UART outside `wq_push_t` + frame policy; the band guard
  equals the MCU dispatch; trigger words 26/27/30 cannot be enabled by any intent (static asserts); word 0 = 0 only
  with `I_POWEROFF`; ranges are checked on the uint16 actually sent; polls stay below 129 words. Recipes and stop
  frames are byte-identical to the captures; stop frames are all zeros; the water stop and the brew sync + start are
  all-or-nothing.
- **Write queue:** ACK must match sub, len and echo; one retransmit at 150 ms, failure 300 ms later (inside stock's
  20 × 10 ms envelope); RX is read before `wq_step`; completion via `seq`.
- **RX parser:** bounded frame length, impossible lengths rejected, no bytes consumed without a CRC verdict, the
  resync watchdog; 180 000 fuzzed frames: 0 lost, 0 extra, no UB. CRC-16/MODBUS matches the captures.
- **Power/boot push/re-push/time base:** the off sequence matches power.md byte for byte; keep-awake only while ON;
  boot push guard on a fresh work_sta; re-push budget ring; 64-bit `ms_t`; wrap-safe counters; DST rules and
  `sched_once_target` correct.
- **Persistence:** `cfg_set_int` ordering (fresh read → backups → number token only → tmp + fsync + read-back →
  rename → fsync dir), every pre-rename failure leaves config.json untouched; MCU first, config second, rollback on
  config failure; the Wi-Fi password never appears in a log; wpa_supplicant.conf quoting; `net_spawn` hygiene
  (double fork, fds closed, fixed argv, no shell strings from config).
- **Boot slot / switch / sound:** `boot_flag_set` (fsync + verify), `bin_is_merakiplus`, `proc_stat`,
  `switch_launch` (closes fds, clock-driven wait, reacquire); one sound helper at a time, `alarm(8)`, `wav_parse`
  bounds (ASan fuzz clean).
- **Renderer:** all drawing clamps to `clipr` ∩ chord mask; register-derived geometry stays in range for any 16-bit
  value; glyph cache bounds; `fit_text` headroom; EN↔DA printf conversions match for all ids; widget ids, row model,
  touch decoding, `jb` bounds and escaping, `rp()` buffers, `js_parse`.
- **Installer:** no shell injection into the root shell (constants, validated pids); md5 gating of local binaries,
  uploads (`.part` before and destination after rename) and copies; atomic temp-file + `mv` replaces on the same
  file system; slot A never written; no reboot anywhere; dry-run guards every mutating call; the output parser holds
  up on a real pty with echo/prompts/CRLF; idempotency of the covered paths.
- **Release workflow:** no `${{ }}` inside `run:` scripts; tag must equal `v<VERSION>`; idempotent create-or-edit;
  `release_notes.py` matches sections exactly; `gen_audio.py --check`, `check_bins.py`, `hygiene.py` match their intent.

## 5. Maintainability

The **module split is done** (`split-modules`): `src/merakiplus.c` is a unity build that `#include`s
`src/mp/{proto,config,net,i18n,bootslot,model,gfx,ui_state,services,ui_pages,runtime,input,sim_hal,main,preview,selftest}.c`
in a fixed order, along the old section banners, with no code change. The fragments still share one scope, so the
couplings the mem-ui-sim reviewer listed remain and are the next steps:

- **The model calls the UI.** `save_step` calls `toast_show`/`detail_close`; `act_guard` returns translated text and
  callers compare pointers (`g==TR(TX_G_NOCFG)`); `ui_update` mixes phase tracking, save/stop progress and boot
  polling with view logic. First step: model functions return enums/ids, the UI maps them to text.
- **Shared mutable globals** across all layers (`reg[]`, `SET[]`, `wq`, `act`, `sav`, `stp`, view state). The SIM HAL
  writes view globals directly (`view`/`page` ~72 references); a small `nav_*` API would end that.
- **Hidden render state:** `cv`/`clipr` swapped by `W_begin`/`arc_paint`; `g_lc` is per-string font state; the widget
  signature cache depends on every caller hashing everything it draws — the likeliest source of future "screen did not
  update" bugs.
- **`home_model`** is domain logic and formatting in fixed 16-byte buffers; split it into a numeric model and a
  formatter.
- **Printf-like helpers** (`jb`, `net_log`, `boot_log`, `sim_die`) lack `__attribute__((format))`; adding it found no
  mismatches and would check ~150 `jb` calls from now on.
- **Build hygiene:** the UI is not built with `-Werror` (43 benign `-Wextra` warnings); fixing them and gating would
  match the other sources.
- v6.20 added one small coupling on purpose: the latched-start-word tracker (`start_latch_track`, `model.c`) takes the
  pending kind as a parameter instead of reading `act` (defined later in `ui_state.c`).
